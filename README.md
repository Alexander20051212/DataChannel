# 🚗 Анализ канала передачи данных CAN

Консольное приложение на C# для анализа временных характеристик передачи сообщений по автомобильной шине CAN. Программа рассчитывает время передачи и задержку доставки сообщений, моделирует приоритетный арбитраж, определяет джиттер и проверяет соблюдение временных ограничений.

**Вариант 1 — «Шина CAN автомобиля»**

## 📌 Возможности

- Загрузка параметров CAN-шины из CSV-файла
- Загрузка списка сообщений и их характеристик из CSV-файла
- Расчёт времени передачи сообщений
- Расчёт задержки доставки с учётом распространения сигнала и обработки
- Моделирование приоритетного арбитража CAN
- Расчёт времени ожидания сообщений в зависимости от приоритета
- Определение задержки доставки с учётом арбитража
- Расчёт джиттера передачи сообщений
- Проверка соблюдения временных ограничений (дедлайнов)
- Вывод результатов анализа в консоль

## 🧮 Реализованные алгоритмы и расчёты

### Время передачи сообщения

Время передачи определяется отношением размера кадра к скорости передачи данных

### Задержка доставки

Полная задержка доставки без учёта арбитража включает время передачи, задержку распространения сигнала и задержку обработки

### Приоритетный арбитраж CAN

В CAN используется приоритетный арбитраж: сообщение с меньшим идентификатором CAN имеет более высокий приоритет.

В программе моделируется ситуация, при которой все сообщения готовы к передаче одновременно. Сообщения с более низким приоритетом ожидают завершения передачи более приоритетных кадров.

Время ожидания определяется суммой времени передачи сообщений с меньшими CAN ID

### Джиттер

Джиттер определяется как разница между максимальной и минимальной рассчитанными задержками доставки

### Проверка дедлайнов

Для каждого сообщения проверяется условие выполнения дедлайна.

Если условие выполняется, сообщение считается доставленным в пределах установленного дедлайна.

## 📋 Исходные параметры варианта

### Параметры CAN-шины

| Параметр | Значение |
|---|---:|
| Скорость передачи | 500 кбит/с |
| Задержка распространения | 0,1 мс |
| Задержка обработки | 0,2 мс |

### Передаваемые сообщения

| Название сообщения | CAN ID | Размер, бит | Период, мс | Дедлайн, мс |
|---|---:|---:|---:|---:|
| EngineSpeed | 0x080 | 128 | 10 | 10 |
| VehicleSpeed | 0x100 | 120 | 20 | 20 |
| CoolantTemp | 0x180 | 112 | 50 | 50 |
| DoorStatus | 0x300 | 104 | 100 | 100 |

## 📊 Результаты работы

Для заданных параметров CAN-шины получены следующие результаты:

| Сообщение | Время ожидания, мс | Время передачи, мс | Задержка доставки, мс |
|---|---:|---:|---:|
| EngineSpeed | 0,000 | 0,256 | 0,556 |
| VehicleSpeed | 0,256 | 0,240 | 0,796 |
| CoolantTemp | 0,496 | 0,224 | 1,020 |
| DoorStatus | 0,720 | 0,208 | 1,228 |

Дополнительные результаты анализа:

- Минимальная задержка доставки: **0,556 мс**
- Максимальная задержка доставки: **1,228 мс**
- Джиттер: **0,672 мс**
- Успешно доставлено сообщений: **4**
- Нарушено дедлайнов: **0**

Все сообщения укладываются в установленные временные ограничения. Наибольшую задержку получает сообщение DoorStatus, поскольку оно имеет самый низкий приоритет среди рассматриваемых сообщений.

## 🛠️ Структура проекта

- `Models` — модели CAN-сообщения и канала передачи данных

- `data` — CSV-файлы с параметрами канала и сообщениями
- `Program.cs` — основной файл приложения

## 🎓 Цель проекта

Изучение временных характеристик каналов передачи данных в системах реального времени на примере автомобильной шины CAN. Практическое освоение методов расчёта времени передачи и задержки доставки сообщений, моделирования приоритетного арбитража, определения джиттера и проверки соблюдения временных ограничений.
